# 학습 차트 실시간 반영 스펙 (2026-11-25)

## 1. 문제

학습 차트는 DB(`learning_candles`)의 마감된 봉만 보여 준다. 진행 중인 봉이 없고, 화면도 한 번 불러온 뒤 다시 불러오지 않아 실제 시세와 차이가 난다.
- 수집기는 미마감 봉을 제외한다(`collectors/binance_spot.py`의 closeTime 조건).
- 수집 주기: 1h 매시 5분, 4h 4시간마다 5분, 1d 하루 1회(UTC 00:10).
- `get_chart`는 DB만 읽고, 프론트는 종목·시간봉 변경과 지표 토글 때만 다시 불러온다.

## 2. 목표와 범위

- 차트 끝에 "DB에 아직 없는 최근 봉"(마감됐지만 아직 수집 전인 봉 + 진행 중인 봉)을 붙여 보여 주고, 화면이 켜져 있는 동안 주기적으로 갱신한다.
- **지표·구조 점수·와이코프·피보나치는 지금처럼 DB의 마감 봉으로만 계산한다**(진행 중 봉으로 값이 흔들리지 않게).
- DB에는 미마감 봉을 저장하지 않는다. 수집기·복기·성과·모의 주문은 건드리지 않는다.
- 범위 밖: 웹소켓 실시간 스트림, 수집 주기 변경, 다른 화면.

## 3. 백엔드

1. `collectors/binance_spot.py`에 최근 봉 조회 함수 추가: 바이낸스 klines를 `limit=5`로 받아 `{open_time, open, high, low, close, volume}` 리스트(시간 오름차순, **미마감 봉 포함**)로 돌려준다. 기존 수집 함수의 동작은 바꾸지 않는다.
   - 같은 종목·시간봉 호출은 10초 캐시(기존 `cache.py` 방식 재사용).
   - 실패하면 예외를 밖으로 내지 않고 빈 리스트(차트는 계속 떠야 한다).
2. `GET /api/learning/chart` 응답에 `live_candles` 추가: 위 결과 중 DB 마지막 봉보다 `open_time`이 큰 것만. DB에 캔들이 없으면 `[]`. 기존 필드(`candles` 포함)는 그대로.
3. 가벼운 조회 `GET /api/learning/live?symbol=&interval=` 추가: `{"live_candles": [...]}`만 돌려준다(같은 규칙, 같은 캐시). 추적 종목이 아니면 차트 API와 같은 404.

## 4. 프론트

1. 캔들 시리즈는 `candles + live_candles`로 그린다. 가격 자릿수 계산도 마지막 실시간 봉 종가 기준. 지표·거래량 칸은 `candles`만 쓴다(실시간 봉의 거래량 막대는 그리지 않는다).
2. 15초마다 `/api/learning/live`를 조회한다. 문서가 보이는 상태(`visibilityState === 'visible'`)이고 차트가 준비됐을 때만. 다른 탭에서 돌아오면 즉시 한 번 조회한다. 종목·시간봉이 바뀌면 이전 조회 결과는 버린다.
3. 조회 결과 처리:
   - 봉 구성이 같으면(첫 봉 `open_time`과 개수가 같음) 차트를 다시 그리지 않고 마지막 봉만 `series.update`로 갱신한다(십자선·확대 상태 유지).
   - 새 봉이 생겼으면(개수나 첫 봉이 달라짐) 차트 전체를 다시 불러온다.
   - 조회 실패는 조용히 넘기고 다음 주기에 다시 시도한다.
4. "최종 갱신" 시각은 차트를 불러온 시각과 실시간 조회 성공 시각 중 늦은 것.
5. 차트 잠금, `clearCrosshairPosition()`, 구조 범위 표시는 건드리지 않는다.

## 5. 테스트 (성공 기준)

- 백엔드: 최근 봉 파싱(미마감 포함), 실패 시 빈 리스트, `live_candles`가 DB 마지막 봉 이후만 담는지, DB가 비면 `[]`, `/learning/live` 응답과 404. 외부 호출은 monkeypatch.
- 프론트: "같은 구성인지/새 봉인지" 판정과 캔들 합치기를 순수 함수로 두고 `tests/learningChartData.test.ts`에 추가.
- 화면: 마지막 캔들의 시각이 현재 진행 중인 봉이고, 15초 간격 조회가 나가며, 조회 후 마지막 봉 종가가 응답 값과 같다. 시간봉 전환·차트 잠금·마우스 올린 채 전환에서 오류가 없다.

## 6. 알려진 한계

- 최대 약 15~25초(조회 주기 + 서버 캐시) 늦다.
- 지표와 구조 점수는 마감 봉 기준이라 실시간 봉의 움직임을 반영하지 않는다.
- 바이낸스 호출 실패 시 실시간 봉 없이 기존처럼 마감 봉만 보인다.
